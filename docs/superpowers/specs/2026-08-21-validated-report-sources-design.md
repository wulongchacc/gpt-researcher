# 报告有效来源闭环设计

## 1. 背景

当前研究流程使用 `visited_urls` 同时表示“尝试访问过的链接”和“可在报告中引用的来源”。检索器取得候选链接后，即使抓取失败，链接仍可能进入 `visited_urls`；报告生成阶段又会把该集合直接追加到参考文献。因此，搜索摘要、抓取失败页面、404 页面和访问受限页面都可能泄漏到最终报告。

已有评测已经改为检查最终报告实际出现的 Markdown 链接，而不是检查所有候选链接。最新结果证明问题不只是评测口径：部分报告实际包含 404、网络错误和超时链接。

## 2. 目标

“全部有效”定义为：报告生成完成时，最终展示的每一条外部链接均通过在线校验。系统不承诺网页以后永久可访问。

本轮目标如下：

1. 最终报告的生成时有效引用率达到 100%。
2. 最终报告不包含未经验证、抓取失败或模型自行生成的 URL。
3. Simple 报告至少保留 2 个有效来源。
4. 主要章节引用覆盖率达到 80% 以上。
5. 来源不足时明确失败或降级，不输出带失效引用的完整报告。
6. 保留候选、可用、实际引用三层来源数据及淘汰原因，支持问题定位和量化评测。

## 3. 非目标

- 不保证链接在报告生成后的未来时间永久有效。
- 不在本轮更换搜索引擎、模型或向量模型。
- 不重新实现网页抓取器。
- 不通过单纯删除无效链接来制造 100% 指标。
- 不继续扩展 Deep Research；首轮验收仍以五道 Simple 题目为准。

## 4. 方案选择

### 4.1 仅在报告末尾删除坏链接

实现成本最低，但会保留没有证据支撑的正文，并通过缩小分母虚增有效引用率，因此不采用。

### 4.2 仅在写作前过滤来源

能够减少坏来源进入上下文，但无法阻止模型生成陌生 URL，也无法处理写作期间失效的链接，因此不足以满足“最终全部有效”。

### 4.3 双重来源校验与受控引用

采用“生成前准入、来源编号引用、生成后复检”的双重校验。该方案增加少量延迟，但能够形成完整的来源可靠性闭环，是本轮采用的方案。

## 5. 来源状态模型

系统明确区分三类集合：

```text
candidate_urls  搜索返回、尚未验证的候选链接
usable_sources  在线校验和正文校验均通过的可用来源
cited_sources   最终报告实际引用的可用来源子集
```

每个来源记录至少包含：

```text
source_id
original_url
canonical_url
title
clean_content
http_status
content_type
content_chars
sentence_count
checked_at
is_usable
failure_reason
```

`visited_urls` 可以继续用于去重和诊断，但不得再作为报告参考文献的输入。

## 6. 生成前来源准入

### 6.1 默认配置

```env
MIN_SOURCE_CONTENT_CHARS=200
MIN_SOURCE_SENTENCES=2
SOURCE_VALIDATION_TIMEOUT_SECONDS=8
SOURCE_VALIDATION_RETRIES=2
SOURCE_VALIDATION_CONCURRENCY=5
```

字符数基于去除 HTML、导航、广告、脚本和多余空白后的正文计算，不使用响应字节数或 HTML 源码长度。句子识别同时支持中文 `。！？` 和英文 `.?!`。

### 6.2 准入规则

1. URL 必须为合法的 HTTP 或 HTTPS 地址。
2. 请求跟随重定向，并保存最终规范化 URL。
3. 最终 HTTP 状态必须为 2xx。
4. 内容类型必须是可处理的 HTML、纯文本或 PDF。
5. 清洗或解析后的正文不少于 200 个字符。
6. 正文至少包含 2 个完整句子。
7. 内容不得被识别为错误页、登录页或验证码页。

状态处理如下：

| 情况 | 处理 |
|---|---|
| 2xx 且正文合格 | 加入 `usable_sources` |
| 3xx | 跟随重定向，以最终响应重新判断 |
| 404/410 | 立即淘汰 |
| 403/429 | 记录为访问受限，默认淘汰 |
| timeout/network error | 最多重试 2 次，仍失败则淘汰 |
| 正文不足或错误页 | 淘汰并记录具体原因 |

校验优先复用抓取器已经取得的正文和响应元数据；只有适配器未提供必要状态时才补充网络请求，避免无意义的重复抓取。

## 7. 受控引用

可用来源按研究任务分配稳定编号：

```text
S1 -> canonical URL A
S2 -> canonical URL B
S3 -> canonical URL C
```

模型获得来源编号、标题和正文，只能使用 `[S1]` 这类编号引用。报告渲染器根据来源注册表把编号转换为 Markdown 链接。模型输出的原始 URL 如果不在 `usable_sources` 白名单中，必须被拒绝，不得直接进入最终报告。

参考文献列表由 `cited_sources` 生成，不再由 `visited_urls` 生成。相同规范化 URL 只保留一次。

## 8. 生成后复检与修复

报告生成后执行以下步骤：

1. 解析最终 Markdown 中的全部外部链接和来源编号。
2. 检查链接均来自 `usable_sources`。
3. 对实际引用链接执行最后一次在线复检。
4. 淘汰复检失败来源，并记录原因。
5. 如果有效来源数或章节覆盖不足，最多执行一轮补充检索。
6. 使用补充来源重写缺少证据支持的内容。
7. 再次复检通过后才向用户返回报告。

默认约束：

```env
MIN_VALID_CITATIONS=2
MIN_SECTION_CITATION_COVERAGE=0.8
MAX_SOURCE_REPAIR_ROUNDS=1
```

如果一轮修复后仍不满足约束，系统返回“可靠来源不足”的明确状态，并保留已经验证的内容和诊断信息。系统不得为了报告看起来完整而重新加入失效来源。

## 9. 组件边界

### 9.1 生产来源校验器

新增生产代码中的来源校验模块，负责 URL 规范化、在线状态、正文门槛和失败分类。评测代码复用同一套状态枚举和 URL 解析规则，避免线上规则与离线指标再次分叉。

### 9.2 研究流程

`gpt_researcher/skills/researcher.py` 负责把搜索候选交给来源校验器，并只将通过准入的内容加入研究上下文。尝试访问记录和可引用来源分别保存。

### 9.3 报告生成

`gpt_researcher/agent.py` 和 `gpt_researcher/actions/markdown_processing.py` 使用来源注册表生成引用和参考文献，移除 `visited_urls -> References` 的直接通路。

### 9.4 评测

`evals/chinese_reliability` 记录最终报告实际引用、有效引用绝对数量、有效引用率、章节覆盖率、过滤原因和修复轮次。

## 10. 错误处理

- 校验任务并发数固定，避免在 4 核服务器上制造突发请求。
- 单个来源失败不终止整次研究。
- 校验器返回结构化失败原因，不依赖异常字符串统计。
- 403、429、超时和永久失效分开统计。
- 最终复检服务整体不可用时，不宣称报告已达到 100% 有效率；返回可重试状态。
- 日志不得输出 API Key、Cookie 或完整授权头。

## 11. 测试策略

### 11.1 单元测试

- 404/410、403/429、超时重试及 2xx 的状态分类。
- 200 字符和 2 句边界。
- HTML 错误页、登录页和验证码页识别。
- 重定向和 URL 规范化。
- 来源集合分离和去重。
- 白名单外 URL 被拒绝。
- 参考文献只包含实际引用的来源。

### 11.2 集成测试

- 混合有效和无效候选来源时，模型上下文只包含有效来源。
- 最终复检淘汰来源后触发一次补充检索。
- 修复成功后所有报告链接通过验证。
- 修复失败时返回“可靠来源不足”，不泄漏失效链接。

所有自动化测试使用伪造 HTTP 响应，不调用 DashScope，也不消耗 Token。

### 11.3 五题 A/B 实验

固定五道 Simple 题目、模型、搜索器、抓取器、向量模型和服务器配置。旧方案与新方案分别运行，并保存原始报告和逐题结果。失败样本不得删除或选择性补跑。

验收指标：

| 指标 | 目标 |
|---|---:|
| 生成时有效引用率 | 100% |
| 失效链接泄漏数 | 0 |
| 编造链接数 | 0 |
| 每篇有效引用数 | 至少 2 |
| 主要章节引用覆盖率 | 至少 80% |
| 报告成功率 | 至少 80% |

## 12. 交付顺序

1. 封存当前实验结果、配置摘要和 Git 提交号。
2. 编写来源状态与准入规则的失败测试。
3. 实现结构化来源记录和生成前准入。
4. 实现来源编号、引用白名单和参考文献渲染。
5. 实现生成后复检、一次补充检索和失败降级。
6. 扩展评测指标并运行无模型回归测试。
7. 部署服务器，执行一题冒烟测试和五题 A/B 实验。

每一步独立验证和提交，不把多项行为变更混入同一提交。
